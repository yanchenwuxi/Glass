# GlassBox-Unified 融合架构说明

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 基准日期 | 2026-11-09 |
| 融合基线 | GlassBox 1.0.16 + TVBox OSC 源码快照 20261109 |
| 工程目录 | `GlassBox-Unified/` |

---

## 1. 融合目标

把两份工程的优势合成一份可继续开发的新工程：

| 来源 | 保留 / 吸收的能力 |
|---|---|
| **GlassBox 1.0.16** | Kotlin + Compose UI、柔光玻璃视觉、MPV/Exo/IJK 三内核、源格式规范、画面调节、轻量架构 |
| **TVBox OSC** | 成熟 Spider 协议细节、直播频道体系、解析链、历史/收藏 Room 模型、局域网推送、DLNA 投屏、本地文件浏览、EPG |

**原则**：以 GlassBox 为骨架（UI / 播放 / 源引擎），把 TVBox 的生产级能力按模块迁入，而不是把两套 UI 和两套播放器硬拼在一起。

---

## 2. 为什么以 GlassBox 为基

1. UI 已全面 Compose，维护成本远低于 TVBox 的 XML + 多 Activity。
2. 播放内核更现代（MPV + Media3），画面调节已落地。
3. 源格式文档完整，JSON/JS/PY 归一路径清晰。
4. 代码体量小（约 44 个 Kotlin 文件），适合作为融合宿主。
5. TVBox 的 View 体系与迅雷 P2P 体积大、耦合深，整体搬迁性价比低。

TVBox 侧采用「能力抽取」而非「整包拷贝」。

## 4. 模块划分（融合后）

```
app/
├── core/           # 网络、展示名、通用工具（GlassBox）
├── data/           # 统一模型 + AppStore + Room（增强自 TVBox 收藏/历史）
├── engine/
│   ├── source/     # 源引擎：Cms / Js / Py / Jar（GlassBox，对齐 TVBox Spider 接口）
│   ├── parse/      # 解析链、嗅探、超时（从 TVBox parser 抽取）
│   ├── live/       # 直播频道 / EPG（从 TVBox live 抽取）
│   └── player/     # MPV / Exo / IJK（GlassBox，预留 P2P 扩展点）
├── server/         # 局域网推送 / 远程控制（从 TVBox RemoteServer 迁入）
├── dlna/           # 投屏（从 TVBox dlna 迁入，可选）
└── ui/
    ├── screens/    # Home / Detail / Player / Search / Sources / Library / Settings / Live
    ├── components/ # 玻璃组件
    └── theme/      # 柔光主题
```

## 6. Spider 协议对齐策略

两端都认 TVBox 生态标准接口：

```
homeContent / homeVideoContent
categoryContent
detailContent
searchContent
playerContent
```

GlassBox 的 `JsSpider` / `PySpider` / `JarSpider` / `CmsSpider` 已覆盖主路径。  
融合时以 GlassBox 实现为准，仅在边界行为上对照 TVBox 的 `JarLoader` / `JsLoader` / `ApiConfig` 做补强（超时、错误兜底、extend 透传、vipFlags 等）。

**不**再维护两套 Loader。

---

## 7. 播放内核策略

| 内核 | 来源 | 角色 |
|---|---|---|
| MPV | GlassBox | 默认首选（画面调节最全） |
| ExoPlayer (Media3) | GlassBox | 兼容与降级 |
| IJK | GlassBox（blankyn） | 兼容老源 |
| 迅雷 P2P | TVBox | P2 评估后再决定是否引入 |

画面参数（亮度/对比度/饱和度/色相/伽马）继续走 GlassBox `AppSettings`，切内核后重下发。

---

## 8. UI 策略

- 全部 Compose，沿用柔光玻璃设计规范（`docs/01_设计规范_柔光玻璃.md`）。
- 新增 `LiveScreen`（P1），不恢复 TVBox 的多 Activity 栈。
- 源管理、搜索、详情继续用 GlassBox 现有 Screen，按 TVBox 交互习惯微调（批量操作、展示名去后缀等已在 1.0.14/1.0.15 完成）。

---

## 9. 依赖策略

以 GlassBox `app/build.gradle` 为准。  
从 TVBox 迁入能力时：

- 推送：可引入 `nanohttpd`（体积小）。
- DLNA：Cling 体积与维护成本高，默认不进主包，可做成可选 module。
- 不引入 XWalk、老版 Doikki 全量、Chaquopy 以外的 Python 方案。

---

## 10. 目录与包名约定

| 旧（TVBox） | 新（Unified） |
|---|---|
| `com.github.tvbox.osc.*` | 不直接保留 |
| `com.github.catvod.crawler.Spider` | 保留接口名兼容，实现放 `engine/source` |
| `com.glassbox.app.*` | 继续作为主包，新增子包 `live` / `parse` / `server` |

applicationId 使用 `com.glassbox.unified`，与旧包名隔离，可与旧版并存安装。

## 11. 构建与验证

```bash
./gradlew :app:assembleDebug
```

验收清单（骨架阶段）：

1. 工程能同步、能编译（Debug）。
2. 启动后首页 / 源管理 / 设置可用（GlassBox 原能力）。
3. 文档中 P0 项均已落地。
4. 无 TVBox 的 XML Activity 残留在主路径。

---

## 12. 风险与边界

| 风险 | 应对 |
|---|---|
| 直播逻辑与 UI 强耦合在 TVBox Activity | 只迁数据模型与解析，UI 用 Compose 重写 |
| JAR 源 ClassLoader 行为差异 | 以 GlassBox `JarSpider` 为准，对照 TVBox 补测试用例 |
| 包体膨胀 | P2 能力默认关闭或独立 flavor |
| 签名与 applicationId | 新 ID，避免覆盖用户旧数据 |
